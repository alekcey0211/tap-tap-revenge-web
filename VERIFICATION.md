# Проверка веб-версии

Дата: 9 ноября 2026 года.

## Источник

- SHA-256 скачанного APK совпал с ожидаемым.
- Все четыре аудиофайла декодируются Web Audio в Яндекс Браузере.
- Длительность после декодирования: 97,708 / 129,473 / 110,224 / 34,620 секунды.
  Значения в plist примерно на 48 мс больше; для завершения игры используется
  длительность декодированного буфера, а не значение plist.
- При извлечении не запускались Android-код, Lua, старые HTML/JS и SDK.

## Автоматические проверки

`npm test`: 20 тестов, все прошли.

- Границы окон попадания, три одновременные дорожки, неверная дорожка, key repeat.
- Удержания: завершение, бонус ровно один раз, раннее отпускание.
- Серии, множители, Revenge и сброс при промахе.
- Концы траекторий и время пролёта из Lua-темы.
- Полное автоматическое прохождение всех 12 музыкальных карт и калибровочной карты
  без пропусков, лишних нажатий или сорванных удержаний.
- Стабильность аудиочасов при отсчёте, паузе и продолжении.

## Браузер

Проверка через chromium-secure-mcp, Яндекс Браузер 26.10 (Chromium 152), macOS.

- Главный экран: три трека, обложки, четыре сложности, оригинальная кнопка Play.
- Аудио загружается и игровое время движется.
- Полный демопроход Waiting for the End / Easy: 116 попаданий, 0 пропусков,
  0 сорванных удержаний, 100% точности. Экран результатов: 66 400 очков.
- Во время паузы время не меняется; после продолжения игра идёт с сохранённого места.
- В демопроходе сработал Revenge ×8. Деморезультат отмечен как несохраняемый.
- В собранном интервале консоли предупреждений и ошибок не было.
- Скриншот игрового поля: `output/gameplay-desktop.png`.

## Ограничения

Не проводились сравнение с запущенным Android-оригиналом, проверка на физическом
телефоне, измерение аудиозадержки внешней аппаратурой, проверка Safari и Firefox.
Автоматическое прохождение проверяет данные и движок, а не удобство игры человеком.

## Проверка ввода

В браузере отправлены 10 пар событий `keydown`/`keyup` по оригинальным нотам первых
16 секунд Waiting for the End / Easy, включая удержания. В обычном игровом режиме
зарегистрированы все 10 попаданий. Это синтетический ввод через браузерный инструмент,
а не физическая клавиатура. После окончания последовательности следующие ноты
пропускались, как и ожидалось.

## Адаптивность и настройки

- В изолированном iframe с viewport 390×844 список треков, кнопка Play и четыре
  сложности доступны; горизонтального переполнения нет (`scrollWidth = 390`).
  Это проверка мобильной раскладки в настольном браузере, не тест телефона.
- Скриншот: `output/library-mobile.png`.
- Поправка 25 мс сохранилась после перезагрузки страницы. После проверки значение
  возвращено к 0 мс.

После финальной правки HUD дополнительно проверен House Music / Extreme:
на 26-й секунде демопрохода — 164 попадания и 0 пропусков. Скриншот игрового
поля обновлён. Этот браузерный прогон остановлен вручную; весь Extreme проверен
автоматическим тестом движка, а не полным браузерным прогоном.

## Звук на iPhone

После сообщения пользователя о движущихся нотах без звука добавлен запрос
`navigator.audioSession.type = 'playback'` перед созданием/возобновлением AudioContext.
Основание: [комментарий разработчика WebKit](https://bugs.webkit.org/show_bug.cgi?id=237322#c6)
о беззвучном режиме iPhone и Audio Session API в iOS 17+.

23 теста прошли, включая доступный API, отсутствие API и отклонение настройки.
Исправленный `audio.js` доступен по LAN-адресу сервера. Воспроизведение звука на
физическом iPhone после правки пока не подтверждено пользователем.
