# Проверки и публикация Tapbeat

## Рабочая версия

- Предыдущая Canvas-версия: тег `v0.10.4`.
- Стабильная Babylon-версия: номер в `package.json`; первый выпуск — `v1.0.0`.
- Исторический baseline `v0.1.0`: `8a55780aaa62cd1bf0e95e6ba4023b5ef1bbea96`.
- Разработка: `codex/development`.
- Ветка существующего Pages workflow: `codex/initial-web-port`.

Новые конфигурации workflow действуют только после разрешённого commit/push.
Локальные изменения не меняют настройки GitHub и не защищают ветку на сервере.
Branch protection и защита тегов этим изменением не настраиваются.

## Локальная проверка

В корне проекта выполнить:

```sh
npm ci --prefix prototype
npm run build
npm run test:scene
npm test
node scripts/check-release.mjs
git diff --check
```

Тесты сравнивают текущий движок с сохранёнными результатами 13 исходных карт
в сценариях perfect, revenge и mistakes. Проверка артефакта допускает только
статические файлы из `release`, отклоняет приватные пути, symlink и некоторые
распознаваемые форматы ключей. Она не доказывает отсутствие любых секретов.

## Сборка и переход на Babylon — 1.0.0

`prototype/build.mjs` собирает сцену и адаптирует общие модули из `dist/`.
`scripts/build-release.mjs` переносит результат в `release/`: корень сайта и
совместимый адрес `/prototype/`. Исходный Canvas-клиент из корня `dist/` больше
не публикуется. Нельзя загружать `dist` вместо `release` в Pages.

У стабильной версии убраны подписи STAGE LAB и ссылки на «рабочую версию».
Звук, игровые правила и карты совпадают с принятой Babylon-сборкой. Прогресс
прототипа (`ttr-babylon-save-v2`) используется без конвертации. Если его нет,
переносятся настройки звука старой версии; её рекорды с другой нумерацией
сложности не сравниваются с новыми. Прежние ключи не удаляются.

Идентификатор, scope и start_url установленной корневой PWA сохранены. Новая
оболочка устанавливается в фоне, активируется после закрытия всех старых окон.
При активации выбранные офлайн-треки переносятся из старого корневого кеша или
кеша `/prototype/`: файлы сопоставляются по SHA-256 и размеру, а не по номерам
сложности. Музыка без выбора пользователя не скачивается. Неполный или
повреждённый пакет не считается готовым; при ошибке его исходный кеш остаётся.
Кеш прототипа не удаляется корневым worker.

Полная проверка перед выпуском включает тесты общих модулей, Babylon NullEngine,
публикуемой сборки, миграции настроек и офлайн-пакетов. В браузере отдельно
проверяем именно `npm start` (папку `release`), а не старый исходный клиент.
`npm run start:source` оставлен для проверки общей исходной базы.

Для отката на Canvas восстановить файлы из тега `v0.10.4` новым коммитом,
включая прежний workflow с артефактом `dist`, затем повторить проверки и деплой.
Не очищать localStorage и не переносить теги. Уже открытое приложение обновится
только после закрытия его окон; возврат файлов на сервере не заменяет этот шаг.

## Происхождение baseline

`tests/fixtures/baseline-v0.1.0.json` получен движком и данными из фиксированного
коммита, а не текущим кодом. Тесты читают этот файл и не перезаписывают его. После замены каталога в v0.9.0
исходные 13 карт хранятся в `tests/fixtures/legacy-charts`, вне `dist`. Их SHA-256
и ожидаемые результаты остались прежними.

Для независимого воспроизведения нужен локальный тег `v0.1.0`:

```sh
node scripts/snapshot-baseline.mjs
cmp output/baseline-v0.1.0.json tests/fixtures/baseline-v0.1.0.json
```

Скрипт проверяет commit тега, извлекает файлы через `git show`, запускает исходный
движок во временной директории и пишет результат только в игнорируемый `output`.
Не копировать изменённые ожидаемые результаты поверх fixture ради проходящих тестов.

## GitHub Actions

`checks.yml` проверяет push в development и pull request, имеет только
`contents: read` и не публикует сайт.

В `pages.yml` оба job ограничены release-веткой. Дополнительно команда
`node scripts/check-release.mjs --publish` проверяет `GITHUB_REF` перед упаковкой
артефакта. Для проверки локально можно передать эту переменную; это только
проверка, не публикация.

Проверка YAML и локальные тесты не заменяют реальный запуск GitHub Actions.
После отдельно разрешённого push проверить, что development запускает checks,
не создаёт Pages deployment, а ручной Pages workflow из development пропускает
build/deploy. До такого запуска эти сценарии считаются непроверенными на GitHub.

## Выпуск

9 ноября 2026 пользователь разрешил опубликовать редизайн по основной ссылке,
без отдельного preview. Это промежуточный выпуск интерфейса, а не завершение
всего плана AI-RHYTHM. Проверка на физическом iPhone выполняется после публикации;
локальные и браузерные проверки описаны в `modern-verification.md`.
Точка возврата — неизменяемый тег `v0.1.0`.

В релизе `v0.2.0` CSS, app.js и изменённый Renderer имеют версию в URL.
Новая HTML-страница не должна смешивать новый интерфейс с прежними модулями
из браузерного кеша. При следующих изменениях этих файлов обновлять версию URL.

Не обновлять основную ссылку без приёмки и отдельного разрешения пользователя.
Перед выпуском проверить конкретный commit, тесты, артефакт и интерфейс;
проверку на физическом iPhone отдельно согласовать с владельцем;
зафиксировать новый тег, не перемещая `v0.1.0`.

Если понадобится откат, восстановить выбранный проверенный commit обычным новым
коммитом в ветке публикации, пройти проверки и повторно развернуть сайт. Не делать
force push и не перемещать теги. После появления service worker отдельно проверить
обновление кеша при откате: возврат файлов на сервере не означает немедленное
обновление уже открытых клиентов. Пользовательские сохранения не удалять.

## Ссылки на экраны — v0.10.3

Экраны используют hash-маршруты внутри прежнего URL GitHub Pages, без серверных
rewrite-правил. Например: `#/library`, `#/calibration`,
`#/song/restless-urban-groove-v1?difficulty=3`. Тот же путь работает в офлайн-оболочке;
аудио и карта доступны без сети только для заранее сохранённого трека.

Перезагрузка во время игры, паузы или на результатах открывает страницу песни.
Текущая попытка не восстанавливается и звук автоматически не запускается.
Открытие установленного приложения с иконки по-прежнему использует стартовый
URL манифеста; это не восстановление закрытой вкладки.
